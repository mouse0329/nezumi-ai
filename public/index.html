概要

すべてデバイスの中で完結する

nezumi-aiはサーバーにデータを送信しません。推論からTTSまで、すべてオンデバイスで処理します。

🚫

完全オフライン動作

ローカル推論のみ。VPN Kill Switchで通信を遮断しながら使用可能。プライバシーを最優先に設計。

⚡

マルチバックエンド

  • LiteRT-LM（メイン）— Gemma 4 / Gemma 3n E2B・E4B
  • llama.cpp — GGUFモデル
🖼️

画像生成（LocalDream）

  • Snapdragon NPU: QNNバックエンド
  • その他: MNN（CPU/OpenCL）へ自動フォールバック
  • GemmaがツールとしてSDを呼び出し（ユーザー承認制）
💬

チャット機能

  • リアルタイムストリーミング表示
  • テキスト＋画像の複合入力
  • 会話履歴の永続化（Room DB）
  • セッション分岐・30秒ウォッチドッグ
🔧

エージェントモード

  • アラーム / フラッシュライト
  • Web検索 / 天気
  • カレンダー / Gmail / SwitchBot（開発中）
🛡️

GPU/CPU自動切り替え

GPU推論を優先し、非対応端末ではCPUへ自動フォールバック。LiteRT-LMのKVCacheリセット対応済み。

必要環境

動作要件

LiteRT-LMを安定して動かすにはAndroid 13以降を推奨します。

項目 最小 推奨
Android バージョン 12 (API 30) 14+ (API 34+)
RAM 6 GB 8 GB 以上
ストレージ空き容量 4 GB 8 GB 以上
GPU（LLM推論） 任意 Mali / Adreno 推奨
GPU（画像生成） OpenCL対応（MNN） Snapdragon NPU（QNN加速）
ℹ️
Tensor G3（Pixel 8 / 8a / 8 Pro）について： Mali-G715 GPUはLLM推論はGPUバックエンドで動作しますが、画像生成のQNNバックエンドはSnapdragon専用です。Tensor端末ではMNN（CPU/OpenCL）フォールバックで動作します。

アーキテクチャ

技術スタック

Jetpack Composeを中心にClean Architectureで構成。エンジン層は交換可能な設計です。

[ UI Layer ]          Jetpack Compose / StateFlow
      ↓
[ ViewModel ]         状態管理 / コルーチン
      ↓
[ Repository ]        Room DB（チャット履歴）
      ↓
[ UseCase / Inference Layer ]
      ↓
[ Engine Layer ]
  ├── LlmEngine      LiteRT-LM（メイン）/ llama.cpp（GGUF）
  └── SdEngine       MNN / QNN — Stable Diffusion 1.5
UI/UX: Jetpack Compose
DB: Room
LLMエンジン: LiteRT-LM / llama.cpp
画像生成: MNN / QNN
モデル: Gemma 4 / Gemma 3n E2B・E4B

インストール

ビルド手順

APKリリースからの直接インストール、またはGradleでセルフビルドが可能です。

# 1. リポジトリをクローン
git clone https://github.com/mouse0329/nezumi-ai.git
cd nezumi-ai

# 2. サブモジュールを初期化
git submodule update --init --recursive

# 3. Debug APKをビルド
./gradlew assembleDebug

# 4. Release APKをビルド（署名設定必須 → local.properties 参照）
./gradlew assembleRelease

local.properties の設定

sdk.dir=/path/to/Android/sdk
ndk.dir=/path/to/Android/ndk

# リリース署名（オプション）
STORE_FILE=/path/to/keystore.jks
STORE_PASSWORD=your_keystore_password
KEY_ALIAS=key_alias
KEY_PASSWORD=your_key_password
